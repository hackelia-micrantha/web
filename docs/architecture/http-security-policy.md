# HTTP document security policy

The public web document policy is owned by
`app/services/document-security.server.js`. Route code supplies the response
nonce and cache policy; it does not construct independent security headers.

## Nonce and fail-closed behavior

Normal HTML responses use a per-response CSP nonce generated by the root
loader. The nonce is carried in `X-CSP-Nonce` between the loader and document
header function, then attached to Remix scripts, JSON-LD, navigation code and
analytics.

A missing nonce does **not** mean "no CSP". The fallback policy keeps same-origin
styles, images and readable SSR content available but sets
`script-src 'none'`. This is intentionally fail-closed for execution and is
also suitable for error paths where the root loader may not have produced a
nonce.

Cache policy must preserve each HTML body and its CSP header as one object.
The existing cache/runtime contracts verify nonce freshness and header/body
pairing for rendered documents.

## Allowed origins

The only cross-origin executable/network trust in the normal document policy is
`https://analytics.micrantha.com`:

- `script-src` allows the analytics client only when a response nonce is also
  present;
- `connect-src` permits analytics submissions;
- `img-src` is restricted to `'self' data:`; the site does not require the
  previous wildcard `https:` image allowance.

Adding another executable or network origin is a security-policy change and
should include a reason, tests and ownership.

## Inline style exception

`style-src 'unsafe-inline'` remains a deliberate exception. The current
client-enhanced Mermaid path renders SVG containing generated inline style
content, and the blog index still has a small React inline-style surface.
Removing the exception requires changing those rendering contracts first.

This exception applies to styles only. Script execution remains nonce-bound.

## Cross-origin headers

HTML responses use:

- `Cross-Origin-Opener-Policy: same-origin`;
- `Cross-Origin-Resource-Policy: same-origin`;
- `Origin-Agent-Cluster: ?1`;
- `X-Frame-Options: DENY` plus CSP `frame-ancestors 'none'`.

`Cross-Origin-Embedder-Policy` is intentionally not enabled. The site does not
currently require cross-origin isolation, and enabling COEP would impose
additional CORS/CORP requirements on the cross-origin analytics dependency
without a demonstrated product or security benefit.

## Development differences

Development keeps the same policy shape but permits the Remix development
runtime's WebSocket connections and `'unsafe-eval'`. Those allowances are not
present in production.

HSTS is production-only. The current value is one year without
`includeSubDomains` or preload; changing either requires a domain-wide
operational decision rather than a web-repository-only change.
